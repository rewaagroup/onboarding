# Onboarding

This repository exists so that every Rewaa intern opens a real pull request,
has it reviewed by a person, and merges it.

It holds no application code. Nothing here runs. That is deliberate — the
subject of this exercise is the workflow, not the software.

## Your task

1. Add a file for yourself in [`interns/`](interns/).
2. Add a row for yourself to the table in [`interns/README.md`](interns/README.md).
3. Open a pull request.
4. Respond to your reviewer's comments and update your branch.
5. Merge once it is approved.

Read [CONTRIBUTING.md](CONTRIBUTING.md) before you start. It describes how we
name branches, how we write commit messages, and what a reviewer will look for.

## Expect changes to be requested

Your reviewer will ask you to change something. This is normal and is not a
judgement of your work — it is what code review is. A pull request that is
approved with no comments usually means the reviewer did not read it carefully.

## Expect a merge conflict

Everyone edits the same table in `interns/README.md`, so whoever merges second
will hit a conflict. Resolving it is part of the exercise.
[Resolve merge conflicts](https://github.com/skills/resolve-merge-conflicts)
from GitHub Skills covers this if you get stuck.

## Recording it in Pulse

When your pull request is open, put its URL in the work item in Pulse and set
the status to **Submitted**. Move it to **Completed** after it is merged.
